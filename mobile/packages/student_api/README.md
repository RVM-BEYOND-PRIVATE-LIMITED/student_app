# student_api
The `/v1` surface of Stage 1A: sign-in, linking a student to their admission, consents and
the age tick, Jobs access, the Campus hand-off and the prompts that come back from Campus.

Changes in 0.28.0: `POST /v1/me/link/auto` takes an optional body `{admission_number}` and may answer the state
`needs_admission_number`, while the centre asks for the admission number as a second proof (#211; off unless set).

Changes in 0.27.0: posting and commenting in the community answer 403 `COMMUNITY_MUTED` with `details.until` while
the member is muted after repeated upheld reports (#296; off unless the centre sets it). No new path or field.

Changes in 0.25.0: `POST /v1/public/enquiries` takes `consent_version`, the version of the consent line's text; the
CRM keeps it with the tick on the lead (#276). Picked up by the website's form and the student app.

Changes in 0.24.0: `GET` and `PUT /v1/me/preferences`, the theme (`ThemePreference`, `ThemeChoice`, #450),
reachable before onboarding is finished. Picked up by the student app's generated client and the web version.

Rules every reply follows:

* Errors have one shape, `Error`: `code` is what the app branches on; `message` is English
  for a log or a fallback line and is never shown as the only text.
* Every POST, PUT, PATCH and DELETE needs an `Idempotency-Key` header. The same key with the
  same body replays the first reply (header `Idempotent-Replayed: true`); the same key with
  another body is a 409. A reply that carries tokens is never stored: a replay mints a fresh
  pair for the same session.
* The app sends `X-App-Version`. Below the minimum the server answers 426
  `UPGRADE_REQUIRED` on every route except `GET /v1/config`. The web version sends no
  version and is never gated.
* Money is integer paise (`*_paise`). Phone numbers are never returned in full except the
  student's own, masked, in `phone_masked`.
* Every reply carries `X-Request-Id`; quote it when reporting a problem.
* Onboarding: until the student has ticked \"I am 18 or above\" and given the required consent
  line once, every signed-in route except `/v1/me`, `/v1/me/language`, `/v1/me/sessions`, the
  consent routes, `/v1/me/age-confirmation` and `/v1/me/jobs-access` answers 403
  `ONBOARDING_INCOMPLETE`.
  Withdrawing the line later does not lock the app; it closes Jobs only.
* Stages (plan 8.2): `visitor`, `registered`, `fully_paid`, `alumni`, read live on every call.
  A route that needs a later stage answers 403 `STAGE_REQUIRED` with `details.stage` and
  `details.needed`; a Jobs route answers 403 `JOBS_CLOSED` with `details.reasons`.
